# 威胁模型、隔离约束与边界

本项目是课程分析工具，不应直接暴露到公共互联网；以下约束均与课程评测公平性和可信工程实现相关。

## 信任边界

| 输入/资源 | 可信度 | 执行策略 |
|---|---|---|
| 单函数源码 | 不可信 | 当作文本给 LLM；不在宿主机编译、运行或执行 |
| 历史案例 JSONL | 不可信，来源须用户审核 | 严格配对/字段校验、本地索引；不自动接入外部知识 |
| GitHub URL | 不可信 | 仅 github.com commit URL、严格 owner/repo/SHA 校验；固定主机请求 |
| ZIP 文件及仓库源代码 | 不可信 | 限制大小/条目/路径/符号链接/扩展名，仅摘取源码内容 |
| LLM 输出 | 不可信 | 只允许声明的工具，参数再次校验；没有 shell、文件写入或浏览器搜索权限 |
| `target` 测试标签 | 测试版本路由元信息 | 仅在 SnapshotProvider 使用，不进入模型上下文和 RAG 检索文本 |
| API 密钥 | 秘密 | 仅来自环境变量，不能出现在任何工具日志和报告中 |

## 三条作业红线的工程落实

### 1. 必须是自主 Agent

- 代码使用模型原生 function calling 与 LangGraph 条件节点组合；LLM 可以自行请求更多案例、调用方、被调用方、定义或文件内容。
- 非固定的检索次数和工具调用序列，终止由模型使用 `submit_verdict` 决定。
- 禁止调用 Codex/Claude Code 作为执行环境；也不支持把业务逻辑外包给 Skill。

### 2. 严格成对隔离

- 单个 Agent 运行只构造一个 `DetectionInput` 的 prompt，不传入兄弟版本函数。
- `target=1` 只能访问该修复提交 `parents[0].sha`；`target=0` 只能访问当前提交 SHA。
- GitHub ZIP 只包含对应一个快照的源码文件；没有 git 元数据、git diff、patch、变更记录。
- LLM 的上下文不包含 `target`、测试 idx、仓库 SHA 或修复 URL，以规避捷径推断。
- 评估脚本与模型运行完全分离。若用户将两个版本直接粘贴在同一个 `func` 输入内，接口本身无法语义判别，属于提交数据违规，应在数据准备阶段避免。

### 3. 禁止网络搜索

- **Agent 的工具名单只有** `retrieve_more_cases`, `search_code`, `find_callers`, `find_definitions`, `read_file`, `submit_verdict`。
- 服务器的仓库获取模块只请求 GitHub 固定 API 主机及 codeload 主机；不能由 Agent 指定任意 URL。
- 无 SerpAPI、搜索引擎、任意 HTTP GET、浏览器自动化、`curl` 或 Shell 工具。
- 远程模型 API 是模型推理的必要请求，不等于网页搜索；模型服务供应商行为由其使用条款决定，建议选择不启用供应商侧工具/联网能力的纯聊天补全模型。

## 工程性安全限制

- ZIP 条目超过 25000、单文件超过 2MB、压缩或解压体积超额，拒绝或跳过；禁用 ZIP 路径穿越和符号链接。
- 仅允许 `.c/.h/.cc/.cpp/.cxx/.hpp/.hh/.hxx/.inc/.inl/.ipp` 后缀；不会读 `*.diff`、`*.patch`、`.git` 文件。
- 仓库工具只读、root 始终绑定快照目录，拒绝绝对路径和 `..`。
- 页面只使用 DOM `textContent` 注入源码与分析日志，避免将代码视为可信 HTML。
- 运行次数和文本大小受限。模型服务失败或权限不足时停止并记录错误，禁止凭空补全评测标签。
- 项目没有多租户认证；默认仅监听 `127.0.0.1`。若用于互联网部署，请独立实现鉴权、文件限流和组织隔离。

## 仍需注意

当前预防外部 URL 的 GitHub 主机限制与 URL 解析依赖标准 HTTPS 客户端；若目标环境有代理，须审查代理策略。LLM 对用户源码里的注释或字符串仍可能遭遇 prompt injection，系统提示已显式声明工具输出均为不可信数据，但不能声称完全消除风险。词法级调用定位也不能证明程序绝对无漏洞。
