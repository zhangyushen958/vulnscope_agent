# 测试方案、可复现验证及运行结果说明

## 测试策略

本工程以可离线执行的单元/集成测试覆盖最关键的课程合规性，尤其不通过“真实模型随机输出”来验证工程逻辑。单元测试使用预定的 mock tool-calling responses 验证工具循环是否由模型指令驱动、是否正确收集证据、是否将违规工具拒绝、是否对无效报告失败关闭。

```bash
python -m pytest -q tests/
```

## 覆盖维度

| 测试文件 | 测试范围 | 核心检查点 |
|---|---|---|
| `test_rag.py` | 知识与配对数据 | 配对/单行两种格式、拒绝重复、不允许模糊配对、知识原子导入、相似检索和测试重合排除 |
| `test_repository.py` | URL/ZIP/快照安全 | GitHub URL 限制、前后版本 SHA 严格选择、无父提交拒绝、恶意 ZIP 路径/符号链接过滤、读仓库边界、候选调用关系 |
| `test_agent.py` | 自主推理和工具执行 | 自主检索→调用→反馈循环、无仓库时工具权限收紧、拒绝未授权工具、超步数失败、无历史数据不伪造知识、目标标签不进入 prompt |
| `test_api.py` | Web & 持久化端到端 | UI 可访问、单条任务状态、实时 SSE、批量处理、导出字段、RAG 上传、重复 idx 拒绝、无模型密钥时不伪造结果 |
| `test_evaluate.py` | 课程成对指标 | 四种类别的分类、A/B 降级惩罚、缺失预测拒绝、配对冲突拒绝 |

## 边界回归注意点

- 容错：故意使用不可用的模型/API 密钥时，服务只应产生错误事件，不应产生 `prediction`。
- 越权：`read_file('../anyfile')` 必须失败，ZIP 中 `.git`、`*.diff` 不能出现在快照中。
- 分离：模型请求中不得出现当前测试样本的 `idx`、`target`、`commit_url`；不允许跨样本复用消息。
- 配对：同一 `commit_url` 下多函数对不能用模糊配对求分，必须要求唯一 pair_id。
- 展示：实时 UI 要显示 RAG 命中项、模型决策的工具名称、仓库读取行为、工具参数与部分返回证据。
- 控制：长批次中单条出错应保留其他成功行，但不允许下载缺失条目的正式 `result.jsonl`。

## 真实效果评测（尚不可执行）

课程要求 150 对共 300 条测试样本，预测每条 0/1 后依据 P-C 等计算成绩。仅上传 PPT，无历史数据集/测试集/真实 LLM 密钥，**不能编造 P-C 数字、混淆工程测试通过率和检测准确率**。

正式跑测试时请记录模型名/版本、参数、历史数据条数、数据集版本、每样本耗时、工具调用总次数、RAG Top-K、GitHub API 失败率以及最终 P-C/P-R。调试时可以对不合规样本和仓库网络失败进行修复，但不可用测试集漏洞版+修复版对照作为 Agent 的上下文，也不可使用 diff 或网络搜索获取答案。
